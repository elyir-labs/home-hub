C — there is no broker, because there is nothing left for it to carry

Ask the color question in colors.

The color question only ever needed three particular bytes on the wire. The hub knows which ordering the strip is currently assuming — it is an attribute it can read — so it can work backwards: which color do I ask for, so that a strip assuming grb puts 255 on the second byte? Then it sends that color with the ordinary Matter command every hub already has, and asks the household what they see.

There is no second channel at all. No broker for a strip to find, no token to hand over, no route that gives anything away, no cluster waiting on a Vendor ID, and nothing to explain about strips somebody else commissioned — they all work the same, because it is all standard Matter. The whole of item 2a stops existing rather than being answered.

Against, and it is one thing

The fill cannot be done this way. Lighting up one at a time is fine — that is the firmware’s own business. But the answer has to come back: a number, latched at the moment somebody taps. Matter has no attribute for it, and inventing one is direction A.

So choosing C is choosing something already on this canvas

It means the strip is never asked how long it is — which is direction C of the length question, drawn as Never, argued, not chosen, and kept with its case intact because “it will come back”. It has. Write a generous number of lights, let the surplus fall off the end of the wire, and accept that a wash meant to run the width of a shelf finishes early. The bet that board named is now the whole decision: are the ambient light and the picture follower two products, or one?
