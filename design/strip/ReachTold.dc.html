A — the hub tells it, over a cluster of our own

One more cluster, and the strip is told where we live.

Matter lets a maker add clusters of their own. The hub has just commissioned this strip, so it already has an encrypted session to it — it writes the broker’s name and a token into a vendor attribute, and the strip connects. Nothing new is invented about trust: the session that carries it is the one Matter built.

For

The household does nothing and sees nothing. The hub is already talking to the strip at exactly the moment this needs to happen, over a channel nobody else can read, so the token never crosses anything weaker than the commissioning session itself. And every beat of design/strip/Spine.dc.html survives: the color question and the fill work as drawn, because the broker is there for them.

Against

It needs a real Vendor ID before it can exist. A manufacturer cluster is namespaced by vendor, so this is unbuildable on a test id — it waits on certification, which is the slowest item on the whole list. It also makes the hub a Matter controller doing writes, which is a thing the brain has never been, and it is code only we will ever run.

And the honest worry

A strip commissioned by Apple and later shared to our hub has no such write, because the sharing fabric never ran our code. So this works perfectly for strips our hub took first and not at all for the others, which is a shape the product has to be able to explain in a sentence and currently cannot.
